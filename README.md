# 纸质书阅读助手

把 iPhone 架在书桌旁当摄像头，翻页之后电脑这边自动出中文。手机只管取景，判断和识别都在电脑上做。

对应《AI 纸质书智能翻译阅读器 · 技术与产品方案 V0.1》。这一版把方案里「先做可行性验证」那部分落地成能跑的东西：翻页检测、页面摆正、双页分割、OCR、翻译、三种阅读模式，全都在本地跑，翻译走 Ollama，不联网也不花钱。

## 跑起来

依赖已经装在项目自带的虚拟环境 `.venv` 里，直接启动就行：

```powershell
cd E:\liruiqin\reading-helper
.\.venv\Scripts\python.exe run.py
```

启动后会打印两个地址和一张二维码：

```
电脑端阅读：https://localhost:8443/view
手机端取景：https://192.168.x.x:8443/capture
```

- Windows 第一次会弹防火墙提示，选「允许专用网络访问」，不然手机连不上。
- 手机和电脑要在同一个 Wi-Fi 下。用 Safari 打开取景地址，会提示证书不受信任——点「显示详情 → 继续访问」。这是自签证书，正常现象。
- 手机端务必把自动锁屏关掉，或者让 Safari 一直停在前台。页面里申请了屏幕常亮，但不是所有系统版本都给。

想换个端口加 `--port 9443`；本地调试不加证书用 `--no-tls`（但手机浏览器在 http 下不给开摄像头）。

想做成双击就能用的 exe 和安装包，见 [docs/打包发布.md](docs/打包发布.md)。

## 怎么用

1. 手机摆在支架上，让整本书落进取景框的虚线里。
2. 点「开始取景」。手机开始每隔 0.8 秒回传一张很小的预览图，电脑拿它判断你有没有翻页。
3. 正常看书翻页。电脑发现画面变了一整页并且稳定下来，就让手机抓一张高清图，然后识别、翻译。
4. 电脑这边自动跳到新页。翻译没好的时候继续显示上一页，不会空窗。

没有手机也能试：右上角「设置 / 连手机」→「手动上传书页」，丢一张照片进去就行。

### 三种阅读模式

| 模式 | 长什么样 | 什么时候用 |
| --- | --- | --- |
| 轻量 | 左边原始书页，右边按段落列的译文，鼠标划过段落会在图上框出来 | 快速核对译得对不对 |
| 标准 | 按文档顺序把英文和译文排在一起，标题、图表说明分开 | 连续读 |
| 沉浸 | 直接在原图对应位置上盖中文 | 想看排版原貌 |

三种模式共用同一份识别和翻译结果，切换的时候尽量停在同一个段落上。

## 目录

```
run.py              启动入口：签证书、起服务、打印手机端地址
app/
  config.py         所有可调参数，存在 data/config.json，改完即时生效
  store.py          已处理页面的存放，以及推给浏览器的实时通道
  gate.py           翻页检测状态机
  imaging.py        摆正、双页分割、图像指纹
  ocr.py            OCR 封装（RapidOCR）
  layout.py         OCR 行 → 段落块，判断标题/图表说明/公式
  translate.py      Ollama 翻译，带词表、跨页上下文、结果缓存
  pipeline.py       把上面这些串成一条流水线
  server.py         FastAPI 路由
web/                手机取景页 + 电脑阅读页，都是原生 HTML/CSS/JS
packaging/          打包成 exe 和安装包的脚本
data/               运行期产物：页面图、配置、词表、翻译缓存、证书
docs/               方案落地说明、工作记录、打包发布
```

`data/pages/` 会被自动创建，每页存三张图：`view`（摆正后，阅读用）、`raw`（手机原始照片，核对用）、`thumb`（缩略图）。

## 调参

打开阅读页右上角「设置 / 连手机」，改完立刻生效。常动的几个：

- **翻译模型**：默认 `qwen3:8b`。想译得细一点可以换 `qwen3:14b-32k`，慢 2~3 秒。换模型后缓存自动分开，不会串。
- **翻页判定阈值**：默认 0.30。手边老是有东西晃就调大，翻页老是不触发就调小。
- **需要连续稳定帧数**：默认 3，也就是画面稳住约 2.4 秒才认定翻页。手按住书页不动的时候调大更保险。
- **双页分割**：`auto` 只在横版画面上切；拍单页竖版就设 `off`。日文那种右开本把「左右页顺序」改成 `rl`。

词表在同一个抽屉里，JSON 格式，`{"英文": "译名"}`。翻译时优先照它来，是让术语前后一致最省事的办法。

## 翻译后端

默认走本机的 Ollama：不联网、不花钱、书里的内容不出这台机器。本地模型用的是 `qwen3:8b`，日常够用；想译得讲究一点可以在设置里换成 `qwen3:14b-32k`，慢两三秒。

也可以换成云端。设置抽屉里把「翻译后端」从 `ollama` 改成 `openai`，下面三项填上就行——这是 OpenAI 兼容接口的形状，DeepSeek、Moonshot、智谱、硅基流动都能用，默认值已经预填了 DeepSeek：

```
云端接口地址   https://api.deepseek.com
云端模型名     deepseek-chat
云端 API Key   sk-...
```

API Key 更推荐放环境变量，别写进配置文件：

```powershell
$env:DEEPSEEK_API_KEY = "sk-..."
```

配置里留空就会去读这个环境变量；两边都空着，一开始翻译就会明确报错，而不是逐段刷一串失败。

**换后端之前想一下**：本地方案最大的好处就是书里的文字一个字都不出这台机器，换成云端等于把正文发给对方。缓存是按「后端 + 模型」分开存的，来回切换不会串。

## 已知的坑

- **手挡在页面上**会被当成画面变化。稳定帧数和静默时间能挡掉大部分，但手一直按着不放，几秒后还是可能触发。真触发了一般也就是多识别一页，重复的会被自动认出来并跳回原页。
- **沉浸模式的长段落**：中文比英文占地方，框里塞不下时字会缩到 10px 就不再缩了，改让框往下长，最多长到 1.5 倍高，再长就截断。这跟方案里说的「原位覆盖难以同时保证字体可读性和视觉保真」是同一件事。
- **横屏拍歪的页面**会自动转正（先判断文字是横排还是竖排，再两个方向各试一遍，取读出行数多的那个）。这一步只在认定页面躺倒时才做，正常页面不付这个成本；但方向判断要读两遍半页文字，躺倒的页面会比平时多花两三秒。
- **表格**没有做结构化解析，只当成普通文本块。公式按等宽字排，不做 LaTeX 渲染。
- **页眉页脚**只能靠简单的规则过滤（页码、极短的首尾行），遇到花哨的版式会漏。
- 改了词表不会让已有译文重算，缓存只跟原文和模型有关。
- iOS 上高分辨率静态采集能不能稳定拿到 3840 宽，取决于机型和系统版本。取景页右上角会显示「采集分辨率」，可以自己看实际拿到了多少。

## 重新装环境

如果换了机器：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

翻译要本机跑着 Ollama，并至少拉一个模型：`ollama pull qwen3:8b`。
